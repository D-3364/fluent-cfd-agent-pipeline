**case 文件**：$0

**需求**：$1

> ⚠️ `$0` 是**第一个**参数、`$1` 是**第二个**（下标 0-based）。
> 详见 `/fluent-run` 里那段说明，别"修"成 `$1`/`$2`。

---

## 这个模式和 `/fluent-run` 的区别

| | `/fluent-run`（完整流水线） | `/fluent-quick`（本模式） |
|---|---|---|
| agent | 3 个 + 调度 | **1 个，就是你自己** |
| 独立审查 | 有（审查者不连 MCP，只读落盘证据） | **没有** |
| 人工关卡 | 有（定完规范停下来确认） | **没有** |
| 耗时 | 长（实测一次 78 分钟 / 1.1M token） | 短 |
| 结果可信度 | 有独立背书 | **只有你自己检查** |

**适合**：探索式试算、改参数看效果、复现已知案例、路径不熟时先跑通。
**不适合**：结果要对外交付、要对物理设定负责、算例本身可疑。

## 怎么做

不派 subagent。你自己按顺序做：

### 1. 环境预检（几毫秒，不启动 Fluent）

```bash
.venv/Scripts/python.exe scripts/preflight.py --case "$0" --run-dir runs/<id>
```

它会拦住：接线断裂、case 不存在、网格超 Student 上限、**路径含非 ASCII**。

### 2. 读 references

至少这三份（`.claude/skills/fluent-cfd-pipeline/references/`）：

| 文档 | 为什么 |
|---|---|
| `solver-api-26.1.md` | 求解驱动 API。**尤其 §1 时间推进** —— MCP 的帮助文本在那里是错的，照它写会静默跑错 |
| `mcp-tool-truths.md` | 工具签名、沙箱边界、非 ASCII 路径 |
| `spec-schema.md` | 只有在你要写验收判据时需要 |

### 3. 连 Fluent、勘察、求解

按 references 里的写法。两条最容易踩的：

- **`connect` 拉起的会话是空的** —— MCP 不暴露 `read_mesh`，网格要自己载
- **`connect` 要传 `cwd`** —— 不传的话 `.trn` 会堆在项目根

### 4. 出结果

产物放 `runs/<id>/`，**至少要有 `report.md`**。

因为没有审查者，报告要自己写清：做了什么、关键数值是什么、**以及你没验证的部分**。

---

## 唯一的硬要求

**报告里必须有一节「我没验证什么」。**

轻量模式省掉的正是审查，所以你必须自己把那部分补上 —— 否则读者分不清
"验过了"和"没验"。这条不能省，理由是它和审查 agent 的 `cannot_verify`
是同一个原则：**不把没查的东西说得像查过。**

## 什么时候该换成完整流水线

跑到一半发现下面任一情况，**停下来，改用 `/fluent-run`**：

- 物理设定不确定（湍流模型、边界条件类型、y+ 是否匹配）
- 网格质量存疑，或结果对不上量级估算
- 这个结果要给别人看
